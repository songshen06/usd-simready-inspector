What The Workflow Did
  • Asset identification: classified as decor and compared with 36 similar reference assets for sizing and collision strategy.
  • Size handling uses 8 x 8 x 10 cm as the reference target range and applies a uniform scale of 0.04 to preserve proportions; the final authored bbox is about 3.96 x 2.68 x 8 cm. The reference target is a physical-size constraint, not a forced non-uniform stretch.
  • Orientation handling converts the source asset from Y-up to the output stage's Z-up convention, implemented as a 90-degree rotation around the X axis.
  • Collision handling: authored convexDecomposition collision approximation on the target mesh, scope=per_component, so downstream physics tests can load it.
  • After adding collision and physical properties, downstream tools can load the asset as an object that participates in simulation, not just as appearance-only geometry.
  • Used downstream mesh-defect feedback to author a lightweight Physics Proxy Collider at /World/PhysicsProxy/BBoxCollider, while preserving the visual mesh.
Tests And Validation
  • The omni-asset-cli Stage 1 static validation did not fully pass. It mainly found 3 material-path conformance findings, geometry-quality findings (ManifoldChecker=1, WeldChecker=1). These findings do not negate the automated authoring result, but they should feed the next automated repair iteration.
  • The runtime validation completed 240 simulation frames: the asset loaded, static colliders were applied, the dynamic test object was created, simulation advanced, and the authored asset kept its size in the template scene.
  • The runtime artifact includes a real PhysX contact report, confirming recorded contact between the test object and the asset.
